# OPC 案例 Excel 导入字段映射表

本文档用于说明 `data/人工智能OPC案例汇总_V2.xlsx` 导入后端数据库时的字段映射规则。

当前 Excel 是案例数据，主要导入三类表：

- `sources`：案例来源表
- `case_items`：案例主表
- `tags`：标签字典表

## 一、地区处理规则

本批次案例必须按省份明确归属。

- Excel `关联地区-省` 必须匹配 `regions.name`
- `case_items.region_id` 按省级地区写入
- `关联地区-市`、`关联地区-区` 暂不作为 `region_id`
- 市区信息会进入 `case_items.business_model`，方便详情页追溯

## 三、sources 来源表映射

| Excel 字段 | sources 字段 | 转换规则 |
|---|---|---|
| `文章名` | `title` | 原样写入 |
| `案例来源（链接）` | `url` | 原样写入 |
| 空 | `source_type` | 固定为 `news` |
| 空 | `publisher` | 暂留空 |
| 空 | `local_file` | 暂留空 |
| 导入当天日期 | `accessed_at` | 使用导入日期 |
| 导入信息 | `notes` | 写入文件名、批次、Excel 行号、市区信息 |
| 空 | `status` | 固定为 `published` |

导入批次标记：

```text
import_batch=case_excel_20260708
```

## 四、case_items 案例表映射

| Excel 字段 | case_items 字段 | 转换规则 |
|---|---|---|
| `文章名` | `title` | 原样写入 |
| `关联地区-省` | `region_id` | 匹配 `regions.name` |
| `案例类型` | `category` | 原样写入 |
| `主体名` | `actor_name` | 原样写入 |
| 导入生成的来源 ID | `source_id` | 插入或匹配 `sources` 后回填 |
| `100-300字摘要` | `summary` | 原样写入 |
| 地区、类型、发布日期等 | `business_model` | 拼接文本 |
| `用到的AI工具或能力` | `ai_tools` | 原样写入 |
| `结果（效果、成果、数据）` | `outcome` | 原样写入 |
| 自动生成 | `tags` | 案例类型、大学生创业标记、AI 工具关键词 |
| `案例来源（链接）` | `original_url` | 原样写入 |
| 空 | `local_file` | 暂留空 |
| 导入当天日期 | `accessed_at` | 使用导入日期 |
| 空 | `status` | 固定为 `published` |
| 空 | `reviewer` | 固定为 `case-excel-import` |

## 五、business_model 拼接规则

因为当前 `case_items` 表没有独立的省市区、发布日期、大学生创业字段，所以这些信息先写入 `business_model`。

格式示例：

```text
地区：江苏省 / 苏州市 / 相城区
案例类型：动漫短剧
是否为大学生创新创业：否
发布日期：2026-01-26
```

## 六、tags 标签规则

案例导入时会写入 `tags` 字典表，`tag_type` 固定为：

```text
case
```

标签来源：

- `案例类型`
- `是否为大学生创新创业 = 是` 时增加 `大学生创新创业`
- 从 `用到的AI工具或能力` 中按 `；`、`、`、`,`、`，` 拆分部分关键词

每条案例最多保留 8 个标签，避免标签过长、过散。

## 七、去重规则

导入 `sources` 时：

1. 优先按 `url` 去重
2. 没有 URL 时，按 `title + import_batch` 去重

导入 `case_items` 时：

```text
title + actor_name + region_id
```

这能避免同一篇文章中不同主体、不同地区案例被错误合并。
