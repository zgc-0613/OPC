# FindOPC 论文数据整理与回写规范

## 目标

把 `findopc.online` 的网站数据整理为可复现的论文数据快照，并在人工清洗后安全回写网站。原始快照始终保留，不在原文件上覆盖修改。

## 阶段范围

1. 当前阶段：中国政策、案例、来源、地区和标签。
2. 后续阶段：国外案例。国外案例必须增加国家、OPC 定义和可比性口径后再并入。
3. 后续阶段：高校 OPC 社区与支持措施。高校数据使用独立实体和独立纳入标准，不从案例文本中强行推断。

## 快照结构

管理员通过 `/api/admin/export/paper-dataset.xlsx` 导出完整快照。工作簿包含：

- `README`
- `sources_full`
- `policies_full`
- `cases_full`
- `regions`
- `tags`
- `tag_aliases`
- `policy_tags`
- `policy_industry_tags`
- `case_tags`
- `data_audit`

每条来源、政策和案例都保留数据库 ID、证据修订号、创建时间和更新时间。关联记录同时显示来源状态、来源证据状态和完整地区路径。

## 完整性规则

“完整导出”表示每一条数据库记录都进入快照；不表示数据库中的每一条记录本身已经完整。

`data_audit` 对每条记录给出：

- 必填字段是否完整；
- 缺失必填字段；
- 缺失建议字段；
- 发布状态；
- 证据状态；
- 关联来源状态；
- 是否可进入论文主样本；
- 未纳入原因。

论文主样本的最低门槛是：记录为 `published`、证据为 `verified`、必填字段完整，并且关联来源同样为 `published + verified`。

## 整理层次

数据处理使用三个文件层次：

1. `raw_snapshot`：网站原始快照，只读保存。
2. `cleaned_workbook`：字段标准化、分类重编码、缺失项补充和拟议修改。
3. `analysis_dataset`：通过纳入标准后用于统计与制图的数据。

清洗过程必须保留记录 ID，不能只靠标题匹配。

## 安全回写规则

清洗后的数据不能直接通过无条件 SQL 覆盖生产库。回写必须：

1. 先生成逐字段差异预览；
2. 使用记录 ID 定位；
3. 同时校验导出时的 `evidenceRevision` 和 `updatedAt`；
4. 发生并发修改时拒绝该条更新；
5. 只更新明确确认的字段；
6. 证据相关字段变化后，将证据状态退回 `legacy_unverified`；
7. 记录修改人、修改时间和修改原因；
8. 回写完成后重新执行证据审核，再生成新的论文快照。

## 当前结构性缺口

- 案例的“是否大学生创业”目前不是结构化字段，不能可靠统计。
- 国外案例所需的国家、OPC 定义和中外可比性字段尚未建立。
- 高校 OPC 社区尚无独立数据实体。

这些字段应在对应阶段建模后再纳入统计，不能从自由文本中批量猜测并直接写回。
